# 동기화 상태 관리

현재 5~6개 수준의 사이드 프로젝트를 관리하므로 별도 저장 인프라 없이 Hub의 전용 브랜치에 JSON 파일 하나를 보관합니다.

## 위치와 공개 범위

- 저장소는 실행 중인 Hub이며 브랜치는 `sync-state`, 경로는 `state/repositories.json`입니다.
- 이 브랜치는 코드가 없는 독립 커밋에서 시작하고 상태 파일만 보관합니다. `master`는 코드와 워크플로를 관리합니다.
- 사용자는 비공개 프로젝트도 ID·이름/경로·SHA·시각·결과 같은 동기화 메타데이터 공개를 허용했습니다. 이 정보는 비공개 저장소의 접근 권한을 부여하지 않습니다.
- 코드·README 본문·원문 오류·인증 키·토큰은 상태 JSON에 넣지 않습니다. 기존 비공개 로그 보호도 유지합니다.

## JSON 구조

```json
{
  "schemaVersion": 1,
  "repositories": {
    "123": {
      "repositoryId": 123,
      "fullName": "side-projects-labs/example",
      "defaultBranch": "master",
      "lastSuccessfulHeadSha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "lastSuccessfulAt": "2026-11-12T00:00:00.000Z",
      "lastResult": "success",
      "lastErrorCode": null
    }
  }
}
```

- GitHub 저장소 ID가 상태의 키이며, 경로 변경으로 새 레코드를 만들지 않습니다. 처음 실패한 저장소의 성공 SHA·시각은 `null`입니다.
- `lastResult`는 `success` 또는 `failure`입니다. 실패 코드는 인증·권한·rate limit·요청 실패 및 `EMPTY_REPOSITORY`, `CONTENT_INCOMPLETE`처럼 정해진 코드만 사용합니다.
- 기록된 성공 시각은 처리가 끝난 시각이며 GitHub의 마지막 업데이트 날짜와 다릅니다. 시각은 재처리 판정에 사용하지 않습니다.

## 실행 순서와 성공 기준

1. 상태 브랜치의 커밋을 확인하고 그 커밋의 JSON을 읽어 검증합니다. 브랜치가 처음부터 없으면 빈 상태에서 시작합니다.
2. 조직 전체 저장소를 조회하고 각 저장소의 `defaultBranch` HEAD SHA를 읽습니다.
3. 마지막 수집 성공 SHA와 같으면 본문 조회를 건너뜁니다. 같은 커밋이라면 상태의 성공 시각도 변경하지 않습니다. 저장소 경로·기본 브랜치 이름 변경은 상태 메타데이터에 반영합니다.
4. 신규·변경 저장소는 확인한 SHA에서 파일을 수집합니다. README만 수정된 경우도 재처리 대상입니다. 코드 변경 여부를 판정하는 규칙은 아닙니다.
5. 생략한 수집 대상 파일이 없으면 성공 SHA와 시각을 갱신합니다. 오류·큰 파일 등의 생략은 이전 성공 SHA와 시각을 유지하고 안전한 실패 결과만 기록합니다.
6. 커밋 없는 저장소는 `EMPTY_REPOSITORY`로 기록하고 빈 저장소 개수로 출력합니다. 성공 SHA는 기록하지 않아 다음 실행에서 다시 확인합니다. 빈 저장소 자체는 전체 작업을 실패시키지 않습니다.
7. 모든 저장소 처리 뒤 바뀐 상태만 저장합니다. 일부 수집 실패도 다른 저장소의 성공 및 안전한 실패 기록은 보관한 뒤 종료 코드 1을 반환합니다. 상태 저장 실패도 종료 코드 1로 처리합니다.

현재 성공 체크포인트는 수집 완료만 의미합니다. AI 생성·portfolio-api 반영·승인·발행은 구현되어 있지 않으므로 완료로 간주하지 않습니다. 후속 단계가 추가되면 단계별 성공 SHA와 멱등성 계약을 마련하고 기존 수집 상태를 그대로 최종 반영 상태로 재사용하지 않습니다. 수집 규칙이 달라질 때 동일 HEAD를 재처리할 마이그레이션도 함께 설계합니다.

## 저장과 복구

- 신규 브랜치는 상태 파일만 담은 독립 커밋으로 초기화합니다. 기존 JSON이 같은 경우 새 커밋을 만들지 않습니다.
- 기존 파일 변경은 읽었던 blob SHA를 전달해 조건부로 수행합니다. 충돌을 강제 갱신하거나 자동 초기화로 덮지 않고 실패시킵니다.
- 손상된 JSON·지원하지 않는 버전·허용하지 않은 필드·기존 브랜치의 상태 파일 누락은 모두 실패로 처리합니다. Git 이력에서 정상 파일을 복구한 뒤 다시 실행합니다.
- 목록에서 사라진 저장소의 기록은 보존합니다. 조회 누락을 삭제나 프로젝트 공개 상태 변경으로 해석하지 않습니다.
- 쓰기는 Hub의 `GITHUB_TOKEN`만 사용합니다. 조직 App은 계속 읽기 전용입니다. 같은 concurrency 그룹으로 실행을 직렬화하고, `sync-state` push는 `master` 한정 수집 트리거 대상에서 제외합니다.
